\section{Current Status}

PPO/RL is not part of the active live trading stack. The active live stack is the JEPA event-option static-union package. The bot uses policy gates, static caps, cooldowns, and mechanical exits, not a PPO exit head.

\section{Legacy RL Stack}

The legacy RL implementation lives under:

\begin{lstlisting}
neural/rl/
backtest/backtest_rl.py
neural/run_pipeline.ps1
\end{lstlisting}

It was designed to select option strikes and exits after a GBT entry signal. The architecture included a PPO agent with strike and exit heads plus a critic.

\section{Why It Is Not Live}

The RL layer historically showed failure modes:

\begin{itemize}
  \item exit-head collapse;
  \item premature exits;
  \item worse drawdown than simpler baselines;
  \item difficulty matching live option-chain constraints;
  \item sensitivity to reward scaling and forced hold transitions.
\end{itemize}

The current production package avoids these degrees of freedom and uses an explicit mechanical exit:

\begin{lstlisting}
stop=-60%
tp=1000%
trail=50%/25%
min_hold=30m
max_hold=180m
\end{lstlisting}

\section{When To Revisit RL}

RL can be reconsidered only as a candidate replacement or overlay. It must beat the static-union event-option package under the same gates:

\begin{itemize}
  \item profit factor at least 1.3;
  \item win rate at least 45\%;
  \item completed-month volume at least the production gate;
  \item no feature leakage;
  \item live-equivalent feature and option-chain construction;
  \item successful systemd startup and paper-intent replay.
\end{itemize}

\section{Useful Legacy Lessons}

The old RL work is still useful for:

\begin{itemize}
  \item defining realistic option-chain environments;
  \item studying min-hold constraints;
  \item evaluating strike-selection headroom;
  \item comparing mechanical exits to learned exits;
  \item building future supervised or offline-RL candidate models.
\end{itemize}

\section{Production Rule}

Do not wire RL into \path{systemd/ai_bot.service} unless a new production package and validation report explicitly promote it. The July 2026 service must continue to load the event-option policy and component registry.
