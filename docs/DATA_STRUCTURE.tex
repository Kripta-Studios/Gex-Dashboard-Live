\begin{abstract}
This document defines the data contract used by the current GBT+JEPA pipeline.  The system is built around a timestamped intraday market-state table for SPX, SPY, and QQQ.  That table is enriched with XInputJEPA features, converted into exact 180 minute labels for the direction model, and converted into candidate option paths for 0DTE execution research.  The most important scientific requirement is chronological integrity: training rows, validation thresholds, out-of-sample rows, option candidate labels, and oracle diagnostics must remain separate.
\end{abstract}

\section{Canonical Row Unit}

The canonical row is:

\[
  r_{i} = (\mathrm{ticker}, \mathrm{date}, \mathrm{time}, S_i, \bm{x}_i),
\]

where $S_i$ is the current underlying or proxy spot price and $\bm{x}_i$ is a vector of market-state features available at that timestamp.  Rows are sorted by ticker, date, and timestamp or time.  All time-series operations are performed within ticker-date groups to avoid crossing from one symbol or session into another.

\section{Raw Data Sources}

The option execution layer reads ThetaData-style option-chain files from the configured local directory, including 0DTE Greeks and bid/ask prices.  The relevant scripts load columns such as:

\begin{itemize}
  \item underlying timestamp,
  \item strike,
  \item right, call or put,
  \item delta,
  \item bid and ask,
  \item implied volatility,
  \item theta,
  \item gamma,
  \item underlying price.
\end{itemize}

The option simulator constructs a mid-price lookup by timestamp, strike, and option right.  It also stores Greek lookups so that open-trade state rows can include current delta, IV, and gamma.

The XInputJEPA training dataset separates features into state and input blocks:

\[
  \bm{x}_t =
  [\bm{s}_t, \bm{u}_t].

\section{JEPA-Appended Columns}

The appender writes 42 columns:

\begin{itemize}
  \item 16 state latent coordinates, \texttt{xjepa\_z\_00} through \texttt{xjepa\_z\_15},
  \item 12 input latent coordinates, \texttt{xjepa\_u\_00} through \texttt{xjepa\_u\_11},
  \item latent and input velocity,
  \item short-horizon and long-horizon prediction dispersion,
  \item lagged prediction errors at 30, 60, and 180 minutes,
  \item short/hold/long probabilities,
  \item trade confidence, direction score, entropy, and context validity.
\end{itemize}

\section{Exact 180 Minute Labels}

The direction frame is built by shifting spot price exactly 36 five-minute rows within each ticker-date group:

\[
  \mathrm{future\_spot}_{i,180m} = S_{i+36}.
\]

Then:

\[
  \mathrm{future\_return}_{i,180m} = \frac{S_{i+36}}{S_i} - 1,
\]

\[
  \mathrm{future\_up}_{i,180m} =
  \mathbb{1}\left[\mathrm{future\_return}_{i,180m} > 0\right].
\]

Rows without a valid future spot are dropped.  If \texttt{xjepa\_context\_valid} exists, rows without a valid JEPA context are also dropped.  The future columns are labels and diagnostics; they are explicitly excluded from feature selection.

\section{Leakage Columns}

The direction scripts define a leakage block that must never be used as features:

\begin{itemize}
  \item \texttt{target},
  \item \texttt{time\_to\_target},
  \item \texttt{time\_to\_stop},
  \item \texttt{max\_move},
  \item \texttt{future\_return\_180m},
  \item \texttt{future\_return\_bps\_180m},
  \item \texttt{future\_up\_180m},
  \item \texttt{future\_abs\_bps\_180m},
  \item \texttt{future\_spot\_180m},
  \item \texttt{terminal\_label\_180m}.
\end{itemize}

The existence of these columns in a dataframe is safe only if model feature selection excludes them.

\section{Option Candidate Dataset}

The 0DTE option policy dataset is not one row per market timestamp.  It is one row per signal and delta candidate:

\[
  c_{j,k} =
  (\mathrm{signal}_j, \Delta_k, \mathrm{strike}, \mathrm{premium}, \mathrm{path}, \mathrm{labels}),
\]

where $\Delta_k$ is one of:

\[
  \{0.10,0.20,0.30,0.40,0.50,0.60,0.70\}.
\]

For each accepted \texttt{base\_jepa} signal, the script chooses the option whose actual absolute delta is closest to the target bucket.  It records actual strike, actual delta, entry premium, spread-adjusted premium, contracts, and path labels.

\section{Option Path Labels}

For each candidate, the option simulator reconstructs the future premium path up to 180 minutes.  The dataset stores:

\begin{itemize}
  \item hold-180 exit value,
  \item hard-rule exit value,
  \item oracle best-exit value,
  \item rule exit reason and time,
  \item oracle exit reason and time,
  \item return on risk,
  \item number of valid path points.
\end{itemize}

The hard-rule exit is deployable because it applies stop/take-profit rules forward in time.  The oracle exit is not deployable because it chooses the best future point after seeing the path.

\section{Chronological Splits}

\subsection{Strict OOS Split}

The main frozen split is:

\begin{itemize}
  \item train through March 31, 2026,
  \item test from April 1, 2026 through May 29, 2026,
  \item 2,220 OOS labelled rows,
  \item 105 \texttt{base\_jepa} OOS trades after 180 minute cooldown.
\end{itemize}

\subsection{Walk-Forward OptionValueJEPA Split}

The OptionValueJEPA walk-forward starts after a minimum 12 month training history and tests month by month from August 2023 through May 2026.  The aggregate contains:

\begin{itemize}
  \item 2,100 evaluated trades,
  \item 19,558 candidate rows,
  \item 704,088 dynamic state rows.
\end{itemize}

\subsection{Production Final Split}

The production run trains on all available data.  Its diagnostics are therefore model-history diagnostics.  The last production run used data through May 29, 2026 even though the configured cutoff argument was December 30, 2026.

\section{Incremental Collection}

Daily retraining is accelerated by the collector's incremental logic:

\begin{enumerate}
  \item If the output parquet does not exist, build from the requested start date.
  \item If \texttt{--force-rebuild} or \texttt{--no-incremental} is supplied, build from the requested start date.
  \item If the collector script is newer than the output parquet, rebuild from the requested start date because feature definitions may have changed.
  \item Otherwise, read the last date inside the existing parquet and append only dates after that date up to the requested end date.
\end{enumerate}

This is why a production run can be fast after the full parquet is current.  If the collector was recently edited, the next run rebuilds once.

\section{Artifact Contracts}

Every production 180 minute joblib artifact stores:

\begin{itemize}
  \item fitted LightGBM model,
  \item training medians for imputation,
  \item exact feature list and order,
  \item long and short thresholds,
  \item metadata including cutoff, feature count, horizon, cost assumptions, and validation months.
\end{itemize}

Live inference must use the artifact's feature list, not an independently inferred feature list.  This prevents training/live schema drift.

\section{Conclusion}

The data structure is a set of related chronological tables: base market rows, JEPA-enriched market rows, 180 minute label rows, option candidate rows, and dynamic option state rows.  The critical discipline is to keep live-safe features, future labels, and oracle diagnostics separated.  The current pipeline does that by explicit feature lists, leakage-column exclusions, chronological splits, and artifact-level feature contracts.
