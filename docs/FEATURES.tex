\section{Principle}

Every feature used by the live event-option scorer must be observable at or before the snapshot timestamp. Future option highs/lows, future spot movement, realized PnL, label columns, and post-entry outcomes are forbidden as model inputs.

\section{Live Snapshot Surface}

The feed builds event-option snapshots from:

\begin{itemize}
  \item current 0DTE option Greeks;
  \item current 0DTE option OHLC/premium data;
  \item current and historical spot candles;
  \item prior completed trading-day context;
  \item policy metadata and candidate identifiers.
\end{itemize}

The snapshot is written to:

\begin{lstlisting}
rt_data/YYYYMMDD/event_option_snapshots_latest.parquet
\end{lstlisting}

\section{Forbidden Feature Families}

\begin{itemize}
  \item any column derived from a future exit price;
  \item future option maximum favorable/adverse excursion;
  \item future spot return after the snapshot;
  \item labels such as win/loss, target-before-stop, realized return, future hold result;
  \item same-month model selection evidence used as if it were out-of-sample;
  \item any feature that exists in backtest/training but cannot be reproduced live.
\end{itemize}

\section{Open Interest and Coverage}

When a feature family requires open interest or historical coverage, the production package must record that coverage in its validation evidence. The current validation command uses \texttt{--ignore-raw-thetadata-coverage} only because the policy records the explicit raw-coverage assumption used for this package.

\section{Live Feature Mismatch Handling}

The bot runs with:

\begin{lstlisting}
--strict-event-option-features
\end{lstlisting}

This means missing or invalid live features should fail closed rather than silently falling back to a different feature set.
