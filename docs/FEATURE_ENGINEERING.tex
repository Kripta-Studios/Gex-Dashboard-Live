\section{Goal}

Feature engineering must make the training, backtest, replay, and live paths equivalent. A model can only be promoted if the live feed can reproduce the exact feature families used in validation without looking forward.

\section{Snapshot Time}

For a snapshot at time $t$, allowed information is:

\[
\mathcal{F}_t = \{\text{spot, option chain, OHLC, Greeks, prior completed context observed at or before } t\}.
\]

Forbidden information is anything in $(t,\infty)$, including exit prices, future option highs/lows, future spot returns, and future labels.

\section{Training to Live Equivalence}

The main files involved are:

\begin{lstlisting}
neural/jepa/build_event_option_dataset.py
neural/jepa/event_option_live_snapshot.py
neural/jepa/event_option_live_scorer.py
neural/jepa/event_option_component_live.py
\end{lstlisting}

The production contract requires that features exported by the dataset builder can be reconstructed by the live snapshot builder.

\section{Policy Replay}

Policy replay is a required validation step. It checks that runtime policy logic reproduces historical selected trades without missing or extra keys. A candidate should not be live-ready if the replay cannot explain the trades produced in validation.

\section{Candidate Identity}

Candidate identity is based on ticker, date, time, expiry mode, side, bucket, and policy family. This identity allows comparison between:

\begin{itemize}
  \item historical candidate rows;
  \item runtime replay rows;
  \item live candidate audit rows;
  \item paper order intents.
\end{itemize}

\section{Minute and Entry Alignment}

Live entries are selected from event-option snapshots generated during the entry window. The bot uses regular trading hours and the policy entry window:

\begin{lstlisting}
10:00-14:30 ET
\end{lstlisting}

No model should depend on future rows created later in the day.

\section{Exit Features}

Exit state for an already open live trade may use current premium, current PnL, elapsed hold time, and high water mark observed so far. It may not use the future maximum premium or future close price.

The current live exit is mechanical:

\begin{lstlisting}
stop=-60%
tp=1000%
trail=50%/25%
min_hold=30m
max_hold=180m
\end{lstlisting}

\section{Audits}

Run feature leakage and live drift checks when changing feature code:

\begin{lstlisting}
python neural/jepa/audit_event_option_feature_leakage.py ...
python neural/jepa/audit_live_feature_drift.py --day-dir rt_data/YYYYMMDD --strict-features
\end{lstlisting}

Validation should fail closed when a required live feature is missing.

\section{Practical Rule}

If a feature is easy to compute in backtest but hard to compute live at the same timestamp, do not use it for production. The live feed is the authority for deployable feature availability.
